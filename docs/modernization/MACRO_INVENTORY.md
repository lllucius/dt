- `__linux__`: compiler/platform macro used throughout Unix-like runtime paths.
- `_UNIX_LIKE_`: internal Unix-like path in API and multi-language runtime code.

## Phase 11 blocker audit

Phase 11 reviewed macro groups that currently block CMake promotion, warning
cleanup, or runtime wrapper work. This section is planning documentation only;
it does not approve macro removal or preprocessor simplification.

### CMake parity blockers

- `USE_ALSA`, `USE_PULSEAUDIO`, and `DISABLE_AUDIO` are current Linux audio
  backend defines owned by Autotools probing. CMake currently records audio
  metadata through `src/platform/dt_audio_backend.*`, and accelerated Phase 10
  models these defines as explicit CMake cache options:
  `DECTALK_CMAKE_DISABLE_AUDIO`, `DECTALK_CMAKE_USE_ALSA`, and
  `DECTALK_CMAKE_USE_PULSEAUDIO`. The default CMake state remains equivalent to
  the previous verified metadata: OSS visible on Linux, ALSA and PulseAudio
  off, and audio not disabled. These options still do not replace Autotools
  probing or prove live-audio behavior.
  Future CMake promotion work should prove no-audio WAV output, symbols,
  detailed manifests, and any live-audio behavior before promotion.
  Next high-risk Plan Phase 9 added
  `tools/baseline/check_audio_option_matrix.sh` to capture this state
  repeatably without opening live audio devices. On the current host,
  `DECTALK_CMAKE_DISABLE_AUDIO=ON` reports `DISABLE_AUDIO` metadata,
  `DECTALK_CMAKE_USE_ALSA=ON` reports `USE_ALSA` metadata,
  `DECTALK_CMAKE_USE_PULSEAUDIO=ON` reports `USE_PULSEAUDIO` metadata, and the
  Autotools `--disable-audio` configure row reports
  `AUDIO_DEFINES=-DDISABLE_AUDIO`. ALSA and PulseAudio remain metadata-only
  rows here because `alsa` and `libpulse-simple` development packages were not
  available.
- `HAVE_ICONV` is generated by Autotools and CMake configuration. It should
  remain a generated configure result, not a hand-set source define.
- `DECTALK_CMAKE_ENABLE_LEGACY_TARGETS` and
  `DECTALK_ENABLE_LEGACY_TARGET_SOURCE` are quarantine controls, not runtime
  feature flags. They should remain opt-in and should not be defined by current
  Linux builds except where platform scaffolding explicitly needs them.

### Warning-cleanup blockers

- Language-selection macros (`ENGLISH`, `ENGLISH_US`, `ENGLISH_UK`, `SPANISH`,
  `SPANISH_SP`, `SPANISH_LA`, `GERMAN`, and `FRENCH`) choose dictionaries,
  phoneme tables, LTS rules, and language-specific source behavior. Warning
  cleanup must not merge, rename, or simplify these branches without language
  baselines beyond the current US English WAV coverage.
- Sound and voice feature macros (`LTSSIM`, `TTSSIM`, `TYPING_MODE`, `ACCESS32`,
  `ACNA`, `AD_BASE`, `NWSNOAA`, `USE_VDEF`, `NEW_TILT`, `SLOWTALK`, and
  `VOICE_ROM_*`) remain high-risk. Arithmetic, table, voice-ROM, or timing
  cleanup under these branches needs exact audio, dictionary, and preferably
  phoneme/text evidence.
- Product and demo macros (`BLD_DECTALK_DLL`, `DEMO`, `SAPI5DECTALK`,
  `ACCESS_SOLUTIONS`, `MME_SERVER`, `USE_MME_SERVER`, `AFDRIVER`,
  `DEBUG_DTK_MME`, and `LICENSE_INCREMENT`) should be handled as ownership
  groups. Private tool cleanup is safe only when the selected product path is
  explicit and the relevant installed artifacts or warning budgets are checked.
- Platform compatibility macros (`WIN32`, `__linux__`, `__APPLE__`,
  `_SPARC_SOLARIS_`, `VXWORKS`, `_BIGENDIAN_`, and related target macros) often
  appear inside shared files. Treat warning cleanup in these branches as
  platform/historical-target work, not ordinary local cleanup.

### Platform-wrapper blockers

- `NOMME`, `USE_ALSA`, `USE_PULSEAUDIO`, `DISABLE_AUDIO`, `WIN32`, `__linux__`,
  `__APPLE__`, `_SPARC_SOLARIS_`, and `VXWORKS` shape audio and threading
  behavior around `opthread.c`, `linux_audio.c`, `playaud.c`, and related
  compatibility code. Runtime wrapper work must classify these macros at the
  exact call site before routing through `src/platform`.
- `DECTALK_ENABLE_LEGACY_TARGET_SOURCE` is useful for platform scaffolding
  smoke tests, but it does not prove legacy runtime parity. Future OP/platform
  parity tests should record which legacy macros were enabled and why.

### Future quarantine options

- Keep current Linux defines explicit in both Autotools and CMake, and compare
  generated compile commands before accepting CMake promotion.
- Move historical target experimentation behind existing opt-ins first:
  `./configure --enable-legacy-targets`,
  `-DDECTALK_CMAKE_ENABLE_LEGACY_TARGETS=ON`, and
  `DECTALK_ENABLE_LEGACY_TARGET_SOURCE`.
- Add documentation-only owner notes before source movement for unknown macros
  such as `NEW_PHONES`, `NO_CODEPAGE`, `_CLIENTDATA`, `DTK_TCL_LIBRARY`, and
  `WAVE_FORMAT_08M08`.
- Prefer new smoke or inventory tests over deleting branches. Deletion should
  remain a separate explicit approval item after reproducible behavior evidence
  exists.
